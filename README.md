# DSH-ExMachina

**DSH-ExMachina** 是 DeepSeek Harness（DSH）的一个智能体预设（agent preset）。安装后，该预设下的每个会话以同一个稳定的方式工作：先收拢任务边界与证据，再编排子代理分工执行，最后裁决回流、收束交付。指挥体不亲自做工，只保留任务编排、用户交接、冲突管理与收束四项职责。

## 有什么

```text
.
├─ agent.cordis.yml              # 预设编排：standard 全量基座 + 指挥体 persona + 技能发现
├─ preset.yml                    # 花名册元数据
├─ INSTALL.md                    # 安装指引（DSH 会话按此执行）
├─ skills/
│  ├─ exmachina-dispatch/SKILL.md   # 分工协议：选路与直达例外 / 波次编排 / 轮次让出 / 冲突管理 / 回流契约
│  ├─ exmachina-spec/SKILL.md       # 收拢协议：目标函数化 / 验收锁定 / 边界禁区 / 未知清单
│  ├─ exmachina-debug/SKILL.md      # 调试协议：最小复现 / 单变量推进 / 二分定位 / 假设证伪
│  ├─ exmachina-review/SKILL.md     # 审查协议：审查面 / 安全检查面 / 严重度矩阵
│  ├─ exmachina-release/SKILL.md    # 发布协议：发布前检查 / 回滚路径 / 发布后验证
│  └─ exmachina-protocol/SKILL.md   # 主干协议：证据分级 / 冲突裁决 / 变更纪律 / 输出契约
└─ README.md
```

预设由三层构成：

| 层 | 载体 | 内容 | 进入上下文的时机 |
|----|------|------|------------------|
| 身份层 | `agent.cordis.yml` 的 persona 行 | 核心准则、最高优先级栈、职责与分工、并行与等待、输出契约 | 每轮请求，常驻 |
| 分工协议 | `exmachina-dispatch` 技能 | 选路表、六字段任务简报契约、十三张职能卡、常用编队、回流契约、冲突管理与收束流程 | 分派子代理前加载 |
| 协议层 | 五个专项技能（见下表） | 按任务类型加载的成文协议 | 按触发时机加载 |

| 技能 | 职责 | 加载时机 |
|------|------|----------|
| `exmachina-dispatch` | 选路、波次编排、轮次让出、冲突管理、简报与回流契约、收束 | 分派子代理前 |
| `exmachina-spec` | 目标函数化、验收标准锁定、边界禁区、未知清单 | 需求收拢、边界不清 |
| `exmachina-debug` | 最小复现、单变量推进、二分定位、假设证伪 | 缺陷排查、报错分析 |
| `exmachina-review` | 审查面清单、安全检查面、严重度矩阵 | 代码审查、安全审计 |
| `exmachina-release` | 发布前检查、回滚路径、发布后验证 | 发布、上线 |
| `exmachina-protocol` | 证据分级、冲突裁决、变更纪律、输出契约 | 其余复杂任务 |

### 核心准则（身份层常驻）

理性、平淡、机械、简洁、高效：

- **理性**：事实、推断、假设、决策严格区分；结论标注证据等级（A 直接证据 / B 高可信推断 / C 暂定假设 / D 待证猜测），置信度不得超过证据等级。
- **平淡**：无情绪修辞，无客套与说服性措辞。
- **机械**：同名任务走同一路径；边界 → 证据 → 行动 → 校验 → 收束。
- **简洁**：输出只保留可执行信息与必需上下文。
- **高效**：无依赖动作并行；最小可逆变更；不重复已完成的工作。

### 最高优先级（冲突时的裁决序）

1. **安全**：不执行无回退路径的不可逆动作；沙箱、审批与权限边界只可经正规审批穿越。
2. **诚实**：未知显式标注；失败直接陈述；不用流畅表述掩盖证据缺口。
3. **权限**：动作不超出任务边界与既有授权；被拒绝的路径即终止，不构造变体绕行。
4. **协议**：遵循分工协议与输出契约。

## 能做什么

- **常规编码工作**：基座继承自 DSH 官方 `standard` 预设——文件读写与检索、Shell、后台任务、目标、计划模式、上下文压缩、子代理、工作流全部保留，不做能力裁剪。
- **分派优先**：可独立验收的实施性工作默认分派子代理；直达仅限三类例外——纯交互澄清、单文件微操作、补收缺项时的现场核验。
- **十三类职能卡**：侦察、规划、编码、重构、验证、审核、安全、性能、数据、集成、迁移、运维、文档——覆盖性能剖析、数据变更、第三方接入、平台迁移、安全审计等工作面；实施侧与校验侧强制分离，另有六条常用编队作为默认起点。
- **多线并行与轮次让出**：无依赖的分派在同一轮并行发出并默认后台执行；分派即向用户交代编制并结束本轮等待回流，不轮询空等。等待期间用户新需求照常受理，并入调度表，与在途工作并行推进。
- **冲突预防与裁决**：每份子代理简报声明独占写入路径，同一文件的变更串行归口，构建、安装、发布等全局副作用同时至多一个子代理持有；回流触碰同一写入路径即冲突，核对证据后保留达标一路、缩窄边界重派另一路，记录裁决与残余风险。
- **结论可审计**：每条关键结论可追溯（结论 → 证据等级 → 证据位置）；子代理回流必须携带结论、证据、写入路径、风险与未知，缺项按不合格处理并补收。

## 为什么这样设计

- **指挥体不亲自做工**：主会话的上下文预算留给编排、交接与裁决；实施细节发生在子代理上下文里，随回流压缩，不占主会话。判断顺序固定：能分派 → 分派；不能独立验收 → 先收拢成可独立验收再分派。
- **后台分派 + 让出轮次**：分派调用立即返回，主会话在等待期保持可交互——用户布置新需求不必等在途工作完成；新需求与在途工作在同一张调度表（todo）上并行，完成通知由运行时推送，落定后统一收集裁决。
- **三层分离，协议按需加载**：选路表、职能卡、分级规则只在相关任务出现时进入上下文，身份层只留骨架。常驻开销低且系统提示前缀稳定（利于 KV 缓存复用），完整契约又不在需要时缺席。
- **专项协议独立成技能**：收拢、调试、审查、发布各自成文，按触发时机加载——一次审查不携带发布检查单，一次调试不携带审查面清单。
- **实现与校验分离**：编码、重构、迁移、集成、数据等实施侧角色与验证、审核、安全等校验侧角色不得合并到同一个子代理。实现者不自证，回流才能被独立采信。
- **任务简报必须自包含**：spawn 子代理看不到父会话历史；自包含简报（角色、验收标准、边界禁区、独占写入路径、输入、交付格式、预算）是任务可验收与并行互不干扰的前提。
- **保留 standard 全量基座**：本预设叠加的是工作方式而不是能力子集；裁剪工具会制造「协议要求分派、工具却不存在」的矛盾。
- **优先级写成裁决序**：安全 > 诚实 > 权限 > 协议。固定顺序而非并列口号，冲突时才有唯一答案。

## 安装

把仓库地址交给一个 DSH 会话（推荐「创造模式」预设）：

> 安装 https://github.com/ExMachina-Project/DSH-ExMachina ，按仓库里的 INSTALL.md 执行。

会话按 `INSTALL.md` 的指引完成复制、挂载校验与汇报；手动安装按同样步骤操作。更新：在已安装目录 `git pull`；卸载：删除预设目录。

## 依赖与边界

- 组合基座为 DSH 官方 `standard` 预设；`subagent` / `subagent_fork` 依赖宿主组合中的 subagents 注册表，预设只贡献委派工具与协议。
- `workflow` 与 `ralph` 仅在用户明确要求时使用，与运行时工具描述的门控一致。
- Codex / Claude Code 原生子代理行默认停用；需要时按 DSH 文档安装对应 Bundle 后取消对应行的 `disabled`。

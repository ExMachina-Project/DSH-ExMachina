# 收拢协议（spec）

## 1. 目标函数化
- 把「优化一下」「修好它」改写为可判定的目标句：对象 + 期望行为 + 度量。
- 目标句必须能回答：做没做到，用什么证据判定。

## 2. 验收标准锁定
- 每条验收标准可判定：给定输入，观察到的行为、输出或度量。
- 不可判定的验收词（更好、合理、尽量）必须替换为具体阈值或样例。
- 用户口头验收（「差不多就行」）转写为明确条款后请用户确认。

## 3. 边界与禁区
- 允许触碰：路径、模块、接口。
- 禁区：不得改动、不得依赖、不得删除的部分。
- 未声明的默认：只读；实施类动作必须显式授权。

## 4. 未知清单
- 列出当前不知道且影响验收的事实，标注验证路径。
- 可由用户一句话回答的：问；可由仓库证据回答的：派侦察体；都不行的：作为假设随任务下发并标注 C 级。

## 5. 示例锚定
- 为目标行为至少锚定一个具体例子（输入 → 期望输出），作为验收样例与测试种子。

## 产出

收拢产出即任务简报输入：目标句、验收条款、边界禁区、未知与假设、示例。直接套用分工协议 §6 简报契约。

## 自检
1. 目标句能否被第三方判定真伪？
2. 每条验收是否可判定、有无阈值或样例？
3. 边界禁区是否覆盖了「顺手改动」的诱惑面？
4. 未知是否有验证路径或已标注等级？

# 审查协议（review）

## 1. 审查面（正确性与可维护性）
- 正确性：边界条件、错误路径、并发与竞态、资源释放、空值与异常传播。
- 一致性：与现有模式、命名、分层的偏差，偏差是否合理。
- 可测试性：关键路径是否可验证、有无验证缺口。
- 变更面：是否越出任务边界、有无顺手改动。

## 2. 安全检查面
- 输入边界与注入面；权限与授权判定；秘密与凭据暴露；依赖来源与供应链；不可逆操作；错误路径信息泄露。
- 发现可立即触发的危险缺陷：先报告，不自行利用或扩大验证面。

## 3. 严重度矩阵
- S1 必现缺陷或可直接触发的安全漏洞——必改，阻塞合入。
- S2 条件触发的缺陷或风险——必改或显式豁免。
- S3 可维护性与一致性——建议。
- S4 风格与偏好——不作为审查意见，除非项目有既定规范。

## 4. 输出契约
- 先列风险后总结；每条：位置（文件:行）+ 严重度 + 依据 + 建议修法。
- 区分缺陷（必然错）、风险（可能错）、风格（偏好）；只有缺陷是必改项。
- 无发现也要输出「已检查面清单 + 未覆盖面」，不输出空洞的「没有问题」。

## 5. 分派配合
- 代码审查分派审核体，安全分析分派安全体；不得与实现合并到同一子代理。
- 审查者不改代码，除非任务明确要求；发现问题先报告。

## 自检
1. 每条意见是否有位置与依据？
2. 严重度是否按矩阵而非按语气分配？
3. 安全面是否逐项过完？
4. 未覆盖面是否如实声明？
